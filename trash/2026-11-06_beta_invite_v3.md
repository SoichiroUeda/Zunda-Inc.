## 1. アルファ週、ありがとうございました

11/1（日）のデモでは、仕様書の「完成の条件」7 項目がすべて動きました。1 週間で、入力 → タイムライン → AI との交渉 → 反映までつながるアプリができたのは、皆さんのおかげです。

使ってみて、次に直したいこともはっきりしました。

- 空いた時間（「ドラマを見る時間」）がタイムラインに見えない
- 夕食・風呂が「明日に回す」になる、買い物が深夜に置かれる
- AI の案が「削る」だけになりやすい

このあと、**ベータ版**に進みます。続けるかどうか・どの役割で続けるかは、皆さんが自分で決めてください。この資料は、その判断の材料です。アルファに参加できなかった人も、ここから参加できます。

## 2. ベータ版でやること

**ゴール：** 京大マーケの部員に配って、**部内テストに回せる状態のプライベートベータ**を作ること。11/30（月）に配布し、12 月に部員に 2〜3 週間使ってもらって、「就寝時刻が早くなったか」を確かめます。

### 2.1 必ず作るもの

| # | 内容 |
| --- | --- |
| 1 | アルファの機能（入力・タイムライン・AI の交渉・完了チェック）の安定化 |
| 2 | iPhone・Android の両方で配布できる |
| 3 | 匿名ログイン（名前やメールアドレスの登録なし）＋クラウド保存（Firebase） |
| 4 | 翌朝の入力画面：就寝時刻・起床時刻・「スッキリ起きられたか」（3 段階）を記録 |
| 5 | 限界時刻の通知 |
| 6 | AI の API キーをアプリに置かない仕組み |
| 7 | 初めて開いたときの同意画面と、プライバシーポリシーへのリンク |

### 2.2 アルファで出た改善（候補・担当と相談して決めます）

- 空いた時間（自由時間）をタイムラインに出す
- 「延長だけ」の案をアプリが足す（延長の案ばかりが目立たない見せ方で）
- 「毎日のタスク」と「何時まで」を入れられるようにする（夕食・風呂を明日に回さない、買い物を深夜に置かない）

## 4. 役割

| 役割 | 主な仕事 |
| --- | --- |
| 開発 | 2 章の機能を、Claude Code と一緒に作る |
| iPhone 担当（開発のうち 1 人以上） | iPhone 版のビルドと動作確認、TestFlight での配布。Mac が必要（貸し出しも相談できます） |
| Android 担当（開発のうち 1 人以上） | Android 版のビルドと動作確認、Firebase App Distribution での配布。Windows・Mac のどちらでもでき、Android のスマホがあると確認しやすい |
| マーケティング | テスター募集、ベータで測るものの設計、「使う前」の記録、テスト中のフィードバック集め |
| UX/UI | 画面の使いやすさ、通知の出し方・文言（開発と兼ねても構いません） |
| 同意書・プライバシーポリシー | テスターに見せる同意書と、プライバシーポリシーの文面を用意する（〜11/20）。下書きは AI と一緒に作れます |

役割はアルファと違うものを選んでも、2 つを兼ねても構いません。

## 8. サポート

- 開発に使う有料 AI ツール（Claude Code）の費用は、引き続きオーナーが負担します。
- iPhone 版の確認用に、Mac（M1・M4 の MacBook Air）を貸し出せます。
- Git や環境の準備で詰まったら、まず AI（Claude Code）に、エラーの文面をそのまま貼って聞いてみてください。たいていはそれで解決します。それでも進まなければ、オーナーに相談してください。

## 9. 作り方で変えること（ふりかえりから）

- 毎日の 1 行報告と、途中でも早めの push・下書きの PR
- 同じファイル（pubspec など）は担当を 1 人に決める
- レビューで直してほしい点は、最初にまとめて伝える
- AI ツールに GitHub CLI（`gh`）を入れて、Issue や PR を直接読ませる
- PR の変更を AI に「初心者向けに 3 行で」説明させて、PR に書く
