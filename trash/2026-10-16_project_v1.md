## 1. プロジェクト概要

| 項目 | 内容 |
| --- | --- |
| プロジェクト名 | 睡眠死守型タスク管理アプリの開発と普及（アプリ名：Rism・仮称） |
| コンセプト | 「睡眠を死守する」オーダーメイド型 AI タスク管理アプリ |
| ターゲット | 「気づいたら深夜2時」になりがちな大学生・若手社会人 |
| 運営 | ずんだ株式会社（予定） / 京都大学マーケティング研究所（京大マーケ） |
| 期間 | 12月末までの約3ヶ月間（まずはここまで） |
| 活動ペース | 週あたり数時間以下（自分のペースで無理なく） |
| 参加条件 | プログラミング経験不問・初心者歓迎 |

### 1.1 解決したい課題

- 深夜のスマホ・ダラダラによって就寝時刻が後ろにずれていく。
- 根性論ではなく、**AI × 時間管理の仕組み**で「決めた時間にスッとベッドに入れる」状態をつくる。
- アプリの役割はあくまで**時間・タスク管理**。その結果として就寝時刻を守る。

### 1.2 京大マーケでやる意味

- アイデアを形にするだけでなく、料金プラン設計・ユーザーテスト・マーケティング検証まで、**ビジネスのリアルを実践形式で学べる**。
- 部員自身がターゲット層（大学生）であり、小さな集団での試運転→実績づくりができる。

### 1.3 開発方針

- **Vibe Coding**（Claude Code 等の AI 主導開発）で、超高速・低コストに MVP を構築する。
- まず動くものをつくり、部内ベータで検証してから拡張する。

## 2. 機能構想（全体）

### ① AI タイムライン自動最適化【コア機能】

- **固定予定 × タスクのパズル化**：授業・バイトなどの「固定予定」と、やりたい「タスク・ルーティン」（所要時間つき）を登録すると、空き時間を埋めた 24 時間タイムラインを自動生成する。
- **限界時刻（Bedtime Lock）の提示**：各タスクの所要時間から逆算し、「明日すっきり起きるために作業を終えてスマホを置くべき限界時刻」を表示する。
- **睡眠時間の確保を最優先**に調整する（睡眠の質を上げる要素も考慮）。

### ② AI との対話による微調整

- **対話型インターフェース**：「今日しんどいから緩めにして」「15分でできることある？」などの自然言語でタイムラインを修正する。
- **タスク巻き返し（ワンタップ再調整）**：予定が押したとき、「風呂をシャワーのみにして15分短縮」「このタスクは明日の移動時間に回す」などの代替プランを複数提示する。
- **前倒し・後ろ倒し**：タスク単位で前後に動かせる。

### ③ スマホいじり防止・通知

- **タスク開始前通知**：タスク開始の 1 時間〜30 分前にプッシュ通知。
- **限界時刻の通知**：限界時刻が近づいたらローカル通知。
- **スマホいじり検知**：夜間などに画面オンが続いたら「いじってて大丈夫？」「そろそろ寝る準備をしませんか？」と表示する。

### ④ 学習・フィードバック

- **初回の所要時間計測**：インストール直後は、ユーザーが実際にタスクをこなす時間を計測して所要時間の初期値にする。
- **翌朝の「目覚めフィードバック」**：「スッキリ起きられたか？」を 3 段階で評価。疲労が残っている場合は各タスクの想定所要時間にバッファを上乗せする。

### ⑤ 入力の手軽さ・連携

- **定番タスクのクイック追加**：ボタンを押すと「洗濯・洗い物・風呂・食事」などの候補がパッと出て、すぐ追加できる。
- **外部カレンダー連携**（Google Calendar 等）：※セキュリティ審査に費用がかかる可能性あり（→ 9 章）。

## 3. ビジネスモデル（案）

### 3.1 基本方針

- フリーミアム（松竹梅スタイル）。
- **AI 呼び出しに回数制限**を設けて API コストの拡大を防ぎ、課金で上限を解放する。
- 無料版は「その日一日限りのタイムスケジュール」、課金版は「一週間・一ヶ月など長期のタスク管理」「他アプリ連携」を追加する方向。
- 補助的な収益源として広告も検討。
- **京大マーケ部員は無料で使えるようにする。**

### 3.2 プラン案（2案あり・未確定）

| プラン | 案A（詳細仕様ドキュメント） | 案B（ブレストメモ） |
| --- | --- | --- |
| 梅（無料） | 基本のタスク管理、簡易タイムライン（AI 呼び出し制限あり） | 回数制限厳しめ・広告あり・Gemini 2.5 Flash／その日一日のみ |
| 竹 | 月額 500 円：AI 微調整・巻き返し提案フル活用、高度な睡眠逆算 | 月額 500 円（2.5 Flash）／月額 1,000 円で回数 2 倍（2.5 Flash）※「一番儲かるように」設計 |
| 松 | 月額 2,000 円：専属 AI アシスタント、行動ログ詳細分析、限定コミュニティ | 月額 2,000 円：無制限（3.5 Flash） |

→ 価格・プラン構成はベータ期間中にマーケティング担当を中心に検証して決める。

### 3.3 想定コスト

- **AI 利用料**：ユーザーの利用量に比例して増える。見積もりは未確定（メモ上では「月3,000円程度？」「60万円〜2,400万円？」など幅がある）。
- **開発コスト**：Vibe Coding で最小化。外注する場合は別途費用。
- その他：アプリ配信・カレンダー連携の審査費用など（→ 9 章）。

## 4. MVP（プライベートアルファ）スコープ

10 月中のアルファ版は、**コア体験の検証に必要な機能だけ**に絞る。

| 機能カテゴリ | アルファ版（10月）で実装 | ベータ版（12月）以降へ |
| --- | --- | --- |
| 認証 | 簡易認証（Apple / Google サインイン） | 詳細プロフィール・SNS 連携 |
| タスク管理 | タスク登録・所要時間入力・完了チェック | 複雑なタグ付け、繰り返しルールの詳細設定、定番タスクのクイック追加 |
| AI スケジュール | タイムライン基本生成 | 外部カレンダー同期、初回の所要時間計測 |
| AI 対話 | 予定調整のテキスト指示（基本プロンプト） | 翌朝フィードバックによる自動バッファ調整 |
| 通知・検知 | 限界時刻のローカルプッシュ通知 | タスク開始前通知、高度なスマホいじり検知 |
| 決済 | 完全無料（ダミー設定） | アプリ内課金（Stripe / In-App Purchase） |

※ 元の仕様に無かった項目（クイック追加・初回計測・タスク開始前通知）は、ひとまず「ベータ以降」に振り分けています。

## 5. 技術スタック・開発環境（推奨）

| 項目 | 内容 |
| --- | --- |
| フロントエンド | Flutter（iOS / Android 両対応） |
| バックエンド・DB | Firebase（Authentication / Cloud Firestore） |
| AI エンジン | Gemini 2.5 Flash API（Google AI SDK） |
| 開発ツール | Claude Code, VS Code, Cursor |
| 開発 OS | **Mac 推奨**（Xcode での iOS ビルド・シミュレータ確認のため） |
| テスト配布 | TestFlight（iOS）/ Firebase App Distribution（Android） |

**アーキテクチャ方針（ハイブリッド構成）**
タイムラインの骨組みはプログラム側の基本ロジックで生成し、ユーザーが微調整を指示したときだけ Gemini API を呼び出す。これにより API コストを最小化する。

## 7. 体制・役割分担

募集資料（recruit.md / recruitdocument.pdf / recruitslide.pdf）の役割定義を基準にしています。

### 7.1 役割

| 役割 | 担当 | 主な仕事 |
| --- | --- | --- |
| リーダー / オーナー | ぷらぐら | 意思決定・全体総括、仕事の割り振り・進捗管理（最高責任者） |
| 開発者・開発責任者 | 募集・調整中 | Claude Code 等の AI を相棒に Flutter / Firebase で実装、Gemini API 連携。経験不問 |
| UX/UI リサーチャー | 募集・調整中 | 画面の使いやすさ・操作体験の検討、通知の出し方・文言の設計、ワイヤーフレーム作成 |
| マーケティング担当者 | 募集・調整中 | どう使ってもらうか・どう広げるかの企画、ベータテスト設計、フィードバック収集・分析 |

### 7.2 全員でやること（ビジネスデザイン）

- 「こんな機能があったら面白そう」「料金プランはどうする？」といったアイデアは、役割に関係なく**みんなで練る**。

### 7.3 開発の進め方

1. Gemini API キー（トークン）を取得する。
2. サークル内に開発できる人がいるか確認する。
3. いなければ外部エンジニアへの外注を検討する。

### 7.4 マーケティングの進め方

1. **小さな集団で試運転**：京大マーケ部員限定（無料）でベータ版を使い倒し、頻繁にフィードバックをもらう。
2. 「本当に就寝時刻が早くなったか」の行動データを集め、実績にする。
3. **大きな集団へ**：一般学生・他大学へ展開する。
