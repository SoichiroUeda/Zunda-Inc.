# AGENTS.md

このリポジトリは、睡眠を守るタスク管理アプリ「Rism」の Flutter アプリです。
（`CLAUDE.md` と同じ内容です。片方を直したら、もう片方も同じように直してください）

## 最初に読むもの

- 仕様書：`docs/alpha_spec.md`。**何を作るかはこの仕様書に従う。**
- 仕様書に書いていない細かい部分は自分で決めてよい。決めたことは Pull Request の説明に一言書く。
- 仕様の意図がわからないときは、作業を止めて人間（オーナー）に確認するよう伝える。

## 説明のしかた

- 開発メンバーにはプログラミング初心者がいる。説明は平易な日本語で、専門用語には一言説明を添える。
- エラーを直すときは、原因と直し方を短く説明してから直す。

## 技術の決め事

- Flutter（Dart）。アルファ版は Web（Chrome）で動かす：
  `flutter run -d chrome --dart-define-from-file=dart_defines.json`
- データは端末内に保存する（`shared_preferences`）。ログイン・クラウド保存はアルファではやらない。
- 状態管理は一番シンプルな方法（`setState` など）。新しいパッケージを入れるときは、理由を Pull Request に書く。
- 時刻は「その日の 0:00 からの分数」の整数で持つ。日付をまたぐ時刻は 1440 以上で表す（例：0:15 → 1455）。表示するときだけ「0:15」に直す（仕様書 4 章）。
- 午前 4:00 で日付が変わるとみなす（仕様書 3.1）。
- タイムラインの計算は、画面とは別の関数（画面に依存しない Dart のコード）にする。仕様書 3.4 の例 1・例 2 を `test/` に自動テストとして置き、`flutter test` が通る状態を保つ。

## AI（Gemini）の呼び出し

- モデルは `gemini-2.5-flash-lite`。モデル名は 1 か所の定数（例：`lib/config.dart`）にまとめる。
- REST API を `http` パッケージで呼ぶ。キーは `x-goog-api-key` ヘッダーで渡す。
- キーはコードに書かず、`const String.fromEnvironment('GEMINI_API_KEY')` で受け取る。
- AI の返事は JSON で受け取り、形をチェックしてから使う。**時刻の計算は AI にさせず、アプリ側で行う**（仕様書 3.6）。
- AI の呼び出しが失敗したとき（10 秒で時間切れ、形が違う等）は、仕様書 3.6 の「予備の案」を出す。

## 絶対にやらないこと

- **API キーを、コード・コミット・Issue・Pull Request・ログ出力に書かない。** `dart_defines.json` はコミットしない（`.gitignore` に入れてある）。キーらしき文字列がコードやコミットに入りそうなときは、作業を止めて知らせる。
- **`main` に直接 push しない。** 作業ごとにブランチを作り、Pull Request を出す。
- 限界時刻を越える配置や、「最低限の睡眠時間」を下回る提案をする作りにしない（仕様書 7 章）。
- テストデータに本物の個人情報を使わない。
